## Vertical slice (full detail)

The single task in Phase 3 that exercises the system end to end against real data. Everything else is scaffolding around this one path.

### What it does

1. **Setup** (one-time, prerequisite): Yumo's `.env` file exists with `OPENSKY_USERNAME` and `OPENSKY_PASSWORD`. Loaded by `python-dotenv` (or equivalent) at module import.
2. **Invoke**: `python -m fleet_tracker.collectors.opensky --tail C-FBOM --hours 24`.
3. **Fetch**: `opensky.fetch_flights("C-FBOM", hours=24)` calls OpenSky `/flights/aircraft` with `begin = now - 24h`, `end = now`. (Phase 0 noted a 1-hour history limit but that may have been about `/states/all`; the slice will instrument and confirm. If the history window is shorter than 24 hours, the call returns whatever OpenSky permits and logs the actual window.)
4. **Cache**: response written to `data/cache/flights/C-FBOM_20260505.json` (date stamp = today's UTC date).
5. **Instrument**: log `estDepartureAirport` and `estArrivalAirport` null counts and percentages. If either exceeds 5%, the slice prints a `WARNING: null rate exceeds 5% threshold from DESIGN §1` line.
6. **Persist to Parquet**: transform OpenSky response → `Flight` rows → write to `data/flights/airline=ac/year=2026/month=05.parquet`. (v1 reads from cache, but the slice exercises the Parquet write once to prove the storage shape works. Subsequent v1 fetches do not write Parquet; v1.5 nightly does.)
7. **DuckDB query**: open `data/fleet.duckdb`, run

   ```sql
   SELECT origin_icao, COUNT(*) AS n
   FROM read_parquet('data/flights/airline=ac/year=*/month=*.parquet',
                     hive_partitioning = true)
   WHERE tail_number = 'C-FBOM'
   GROUP BY origin_icao
   ORDER BY n DESC;
   ```
8. **Print**: aggregate result table to stdout.
9. **Exit 0**.

### Why this slice

- It's the thinnest end-to-end path that touches every layer: HTTP fetch, cache, transform, Parquet write, DuckDB read, aggregate. Anything that's wrong in DESIGN's storage assumptions surfaces immediately.
- It uses a real tail Yumo cares about (per the retrofit tracker fixtures).
- It runs in seconds and produces visible output.

### Fallback

If C-FBOM has no flights in the OpenSky-permitted window at slice runtime, fall back to **C-GROV** (A321ceo). Reasoning: 787-9 widebodies on long-haul transatlantic / transpacific routes have known OpenSky coverage gaps over oceanic airspace and can return zero flights even when the aircraft is active. C-GROV is narrowbody on dense North American ADS-B coverage and is therefore a safer fallback. (This was open question 1 in the Phase 2 review; resolved by Yumo on 2026-05-05.)
